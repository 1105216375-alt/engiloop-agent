# 公开版安全修复：以受限数值 AST 替代动态执行

这项修改是**本次公开副本新增的安全加固**，不是原产品已经具备的历史能力。修改只发生在本仓库的计算器与新模块中，没有修改部署中的生产程序。

## 修复原因

抽取前的 `Calculator._eval_expression` 使用受限 `globals` 调用 Python `eval`；分段规则把数值和条件拼成字符串后再次 `eval`。清空 `__builtins__` 并不等于安全沙箱，属性遍历、传入对象和资源消耗仍需防护。

现在不再执行这些表达式。`engineering_agent/safe_arithmetic.py` 读取 AST 后，仅按明确允许的节点逐步计算。没有使用 `eval`、`exec`、表达式编译执行或任意函数对象调用。

## 三个入口，权限逐级明确

### 1. `evaluate_arithmetic(expression, exact=False)`

只允许：十进制实数常量、括号、`+ - * / **`、一元 `+ -`。支持小数、科学计数法及合法数字下划线。

拒绝：所有变量名、函数调用、属性、下标、列表/字典/集合/元组字面量、字符串、布尔值、复数、推导式、lambda、赋值、条件式、比较式、逻辑/位运算、整除和取余。

```python
from engineering_agent.safe_arithmetic import evaluate_arithmetic

evaluate_arithmetic("0.70*84.33 + 0.18*84.42 + 0.12*84.47")
# 84.363
evaluate_arithmetic("0.1+0.2", exact=True)
# Fraction(3, 10)
```

### 2. `evaluate_formula(expression, variables=None, exact=False)`

提供注册公式所需的有限扩展：明确传入的数值变量，固定常量 `pi`、`e`，以及以下固定函数：

`abs`、`round`、`min`、`max`、`sum`、`len`、`int`、`float`、`sqrt`、`log`、`log10`、`exp`、`sin`、`cos`、`tan`、`floor`、`ceil`。

不是任意调用权限。函数只能以白名单名字直接调用；不接受 `math.sqrt`、属性链、关键字参数、星号展开或用户传入的函数。变量不能覆盖白名单函数和常量。

绑定值仅接受普通 `int`、有限 `float`、`Fraction`，或有限长度且只包含这些数值的普通列表/元组。拒绝布尔值、字符串、嵌套容器、函数和自定义数值对象，避免触发用户对象的转换/运算方法。序列只供 `sum`、`len`、`min`、`max` 聚合，不允许下标、切片或序列运算。

```python
from engineering_agent.safe_arithmetic import evaluate_formula

evaluate_formula("sqrt(L**2 + W**2)", {"L": 3, "W": 4})
# 5.0
evaluate_formula("sum(weights)/len(weights)", {"weights": [.7, .18, .12]})
# 0.3333333333333333
```

`Calculator.compute` 原有的普通数字字符串预处理仍在，因此正常计算接口传入 `"3"` 可以先转换成数字。安全算术模块自身不接受字符串绑定值。

### 3. `evaluate_condition(value, condition)`

用于分段规则，只接受一个比较符 `<= >= == != < >`，右侧为上述严格算术表达式。例如 `>= 80` 或 `< 100-25`。

没有把 `value` 拼进字符串；左右数值分别获得验证后，使用固定比较操作。条件不支持变量名、函数、链式比较、`and/or` 或 Python 语句。

公开计算器先检查全部分段条件，再按原顺序选择首个匹配结果。任何条件非法都会产生失败结果，而不是跳过非法条件后悄悄返回 `default`。这是有意的兼容性收紧。

## 数值语义

- 十进制字面量直接从源码片段转换成 `Fraction`，避免先经历二进制浮点舍入。
- 加减乘除和整数幂在有理数域内精确计算；每一步检查范围及表示规模。
- 非整数幂、三角函数、对数、指数、平方根等使用有限实数浮点计算；`exact=True` 不会把这些近似运算变成形式化精确证明。
- 默认输出整数或有限浮点数，便于原计算器接口使用；`exact=True` 可保留有理数结果。若从非零有理数转浮点会下溢为零，则明确拒绝，不静默给出零。
- `round` 对有理数使用 Python 的精确半偶舍入语义；经过超越函数的结果仍受浮点精度影响。
- 除零、负数非整数实数幂、对数定义域错误、无穷大、NaN、越界与受限资源错误都产生 `SafeArithmeticError`，原计算器将其转为 `success=False`。

## 资源边界

| 资源 | 当前上限 |
| --- | --- |
| 表达式字符数 | 2,048 |
| AST 节点数 / 最大深度 | 256 / 32 |
| 单字面量数字位数 | 128 |
| 科学计数法显式指数绝对值 | 300，仍须通过数值范围检查 |
| 有理数分子/分母表示 | 各 2,048 bit |
| 任意数值绝对值 | `10**100` |
| 幂指数绝对值 | 100，且整数幂计算前检查预计表示规模 |
| 变量数 / 绑定数值总数 | 64 / 512 |
| 单个数值序列长度 | 128 |
| 单次函数参数数 | 32；各函数另有固定参数个数约束 |
| `round` 的 `ndigits` | -12 到 12 的整数 |
| 计算器分段条件数 | 128 |

这些限制用于防止常见巨型幂、深层表达式和长序列耗尽资源，不构成多租户服务的操作系统级隔离。对公网服务仍建议请求大小限制、超时、速率限制和进程资源限额。

## 验证与保留的信任边界

测试覆盖工程加权计算、长度/宽度单位比例、精确小数、数学白名单、合法分段/查表，以及对象遍历、导入、任意调用、下标、巨型幂、超长/过深AST、非法数值、恶意绑定对象、下溢和错误条件不能落入默认结果。

```bash
python -m pytest -q tests/test_safe_arithmetic.py
```

仍需注意：

1. 注册的 Python `callable` 公式仍是可信应用代码，按原设计直接调用；本修复没有把任意 Python 插件变成安全沙箱。不得让终端用户上传并注册任意函数。
2. 查表规则仍按原实现处理。规则定义、查表结构和调用方提供的Python对象应来自受控程序或经过校验的JSON输入，不应接受攻击者构造的活对象。
3. 这只是表达式执行安全与数值计算约束。公式是否符合现行规范、适用哪种桥型、权重是否正确、单位是否一致、测量数据是否真实，仍需要领域规则及工程复核。
4. 这是保守子集，不再兼容旧 `eval` 可能碰巧支持的任意Python表达式。更复杂的运算应以经过审查的工具接口显式实现，而不是扩大成可执行代码语言。
