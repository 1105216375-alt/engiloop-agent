# 残差推理与受审记忆：运行结果，而非静态标签

本节使用抽取的 `domain.reasoning_bridge.BridgeReasoningMode`、`nskernel` 闭环、`EulerMemoryExtractor` / `EulerMemoryMatcher` 和 SQLiteStateStore。
新增的 `engineering_agent/bridge_fixture.py` 仅提供最小领域档案与观察映射，使真实内核可以脱离生产 Web 服务运行。
所有桥名、病害、评分、报告标识和审核人均为合成输入；不加载私有知识 JSON、真实档案、生产配置或模型密钥。

## 运行

```bash
python -m examples.residual_reasoning
python -m examples.reviewed_memory
python -m pytest tests/test_residual_reasoning.py tests/test_reviewed_memory.py -q
```

两个示例都关闭模型风格化，不调用在线模型。记忆使用临时 SQLite，退出即清理。
因此这里验证的是本地推理控制与证据约束，不是大模型效果、现场评分准确率或工程认证。

## 残差：明确还缺什么，并改变能说什么

```text
本次证据 → ResidualState：目标 / 未解决任务 / 未知证据 / 约束
                       ↓
候选步骤 → 闸门校验 → 通过后更新 → 重建剩余任务
                       ↓
StrictOrchestrator 只依据本轮状态组织回复
                       ↓
缺少关键依据时，给条件性结果和补证要求，不补编工程结论
```

示例撤去的是实际输入，而不是事后给答案贴“谨慎”标签：

| 合成条件 | 最终输出应发生的变化 |
| --- | --- |
| Dr、BCI 都有效 | 允许演示规则内的技术状况风险筛查，同时声明不等于承载能力或通行安全结论。 |
| 缺少或无效的 Dr / BCI | 不再给出该路径的交叉风险等级，unknowns 留下对应评分缺口。缺失不换成零。 |
| 数值确实为 0 | 保留真实零值，不误认为缺失。 |
| “未开展荷载试验”“暂无维修记录” | 否定语不能被当成“存在荷载、维修证据”；相关未知项保留，大修决定受限。 |
| 有承载、维修记录描述 | 只消除相应输入缺口；不自动得到是否全桥大修的完整决策依据。 |
| 给出设计寿命与服役年限 | 没有经校准的寿命模型时仍不生成剩余寿命年数，不做“设计寿命减年龄”。 |

`solved` 表示本轮回答任务已形成有边界的结果，不表示桥梁问题被修好或证据全部齐全。
`completion_mode=conditional` 与 `unknowns` 用于表达仍有证据限制；不能只看一个 solved 标签对外宣称“已证实安全”。

### 分值口径

Dr/BCI 是示例手工设置的**合成输入**，不是此示例从病害重算的规范评分。
`bridge_score_52xx` 是沿用的兼容字段名；它不代表一个已发布或现行的标准，不能据此引用所谓“52XX 新规范”。
本示例不发布标准权威性结论。真正部署时须绑定有版本、适用条件与授权来源的规范计算器，并复核上游评分。
同理，Observation 的结构化与 raw_data 导入不等于现场事实被形式证明；上游采集和档案绑定仍须独立核验。

## 记忆：复用受审核的路线，不复用上一座桥的答案

示例不只检查 `memory_applied=true`，而是比较真实被接受的动作顺序及最终回复。

1. **来源桥实际运行**：合成来源桥询问构件维修优先级。内核生成并验证候选，形成 `priority` 路线。
2. **自动提炼为待审候选**：Extractor 提炼步骤模板、适用证据要求和上下文轴；原桥事实与最终答案不进入可复制答案槽。
3. **未审核不能使用**：目标桥询问“风险＋优先级”，第一次仍按当前默认规则先做 `risk_assess`。
4. **明确审批**：示例调用 review_memory_candidate，以合成审核人批准来源路线。真实部署的审核身份与权限需由应用层提供。
5. **新桥重新匹配**：Matcher 只检索 approved pattern，核对任务、范围与必要证据；可用模式作为路线提示进入当前 proposer。
6. **执行顺序确实改变**：目标桥的新一轮先接受 `priority`，后续仍完成 `risk_assess`。候选仍须逐一过同一验证闸门。
7. **事实保持当前桥**：来源桥的 Dr 91、BCI 93、风险 77、锈蚀描述不进入目标桥结论；目标桥继续使用当前合成 Dr 60、BCI 66、分项 44 和裂缝记录。

另一个负例先批准大修分析路线，再撤去目标桥的承载与维修闭环证据：系统可以“检索到”旧模式，但 `can_apply=false`，不会应用该路线。
测试还覆盖“排除已修复项”范围冲突，以及记忆路线没有当前规则候选时回退到当前规则的行为。

## 七轴相位编码的准确含义

`EulerMemory` 当前把任务、意图、时间范围、构件范围、维修范围、证据画像和目标模板编码为确定性上下文坐标，进行硬门控与加权匹配。
这是应用层的结构化记忆检索与路线选择机制，不是模型 KV cache，不是自动训练，不是数学证明器，也不因使用复数表示就得到新的事实真值保证。
相位匹配只能决定是否适用；不能覆盖缺失证据、审核状态或本轮 verifier。

## 本轮公开副本修复：回退和未对齐决定不能提炼成已验证路线

原抽取代码按列表位置对应候选与决定，并在旧记录缺少对齐决定时退回 proposed_actions；它也没有排除同一步后续出现的 rollback 事件。
本轮仅修复公开副本 `bip_runtime/euler_memory.py`：

- 一步出现 rollback 事件，整步不进入可复用路线模板。
- 候选必须具备 candidate_id，且恰好有一个同 ID 的 ACCEPT 决定。
- 缺失、错位 ID、拒绝、相互冲突的决定或仅有累计接受数，都不算已验证步骤。
- 无可用步骤时不生成记忆候选；旧无身份记录仍可保留为审计数据，但不自动升级为可复用知识。

回归测试同时验证未生成模板和未向临时 SQLite 写入候选，并保留正常桥梁路线复用的端到端测试。
这些是本轮公开版的安全收紧；不表示原生产副本已同步修改，也不是对来源日志真实性的密码学证明。

## 已知限制

- 默认桥梁模式的候选由有限启发式规则生成；本示例没有证明任意开放式任务都可自动求解。
- “已验证事实”在该路径还包括上游给出的评分与档案记录；它表示进入此轮证据账本，不意味着所有来源都经过形式化证明。
- 从文本识别“有承载/维修记录”只是一层证据能力检查，不替代报告真实性、资质、时效与适用性复核。
- 记忆批准是必要条件，不是充分条件；更不能拿匹配分当结论正确率。
- 记忆来源运行与审核摘要应保留。本轮已排除明确回退和未对齐的动作；调用方仍须保证日志来源可信，不得人为伪造 ACCEPT 或漏记 rollback。
- 这个示例不执行正式报告签发、派单、计费或其他外部写操作。

可对外准确表述为：**把未知项显式保留到最终回答，把已审核的解题路线用于下一次规划；每次仍绑定当前证据、重新校验，而不是复制旧答案。**
