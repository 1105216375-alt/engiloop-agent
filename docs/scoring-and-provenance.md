# 评分数据流、输入闸门与双轨来源

## 本例证明什么

本例使用抽取的真实 `BridgeScoringAgent`：诊断输入中的 DP 进入构件累积扣分，再进入部位聚合与加权。它证明的是**输入变化确实影响输出计算**，不是仅把某个数字显示在界面上。

这是合成数据、指定部位快照的机制测试，**不是全桥实测结果，也不是对所引规范条文、权重、适用范围或DP选取正确性的独立证明**。

```bash
python -m examples.engineering_scoring
python -m pytest -q tests/test_engineering_scoring.py
```

## 真正沿用与本次新增

`legacy_v7/core/scoring_agent.py` 中的构件递归扣分、部位聚合、权重及 `evaluate_bridge` 保持原样。本次新增 `engineering_agent/scoring.py`，只承担输入边界检查和结果范围控制。

适配器继承原评分器，仅将外部病害数据库加载禁用。示例明确提供DP，因此不需要生产数据库、不读取环境变量指定的规则文件，不会用随意编写的“假评分器”替代原计算。

内部仍真正调用 `evaluate_bridge`。但是原函数可能对没有记录的系统返回默认100分，并给出全桥等级；这些默认系统分、全桥总分、全桥等级及旧摘要**不向本公开入口的调用方交付**。

公开结果只取显式选择且通过覆盖检查的部位，再调用同一个原加权函数，在选择范围内归一加权，命名为 `selected_scope_score`。它不能改名冒充“全桥Dr”。

## DP20→60：数据怎样一路改变

合成输入只含主梁、支座两个部位，各一个明确编号实例：

| 输入或结果 | 第一次 | 只改变主梁DP后的第二次 |
| --- | --- | --- |
| 主梁DP | 20 | 60 |
| 支座DP | 10 | 10 |
| 主梁构件得分 | 80 | 40 |
| 支座构件得分 | 90 | 90 |
| 选中范围归一加权分 | 81.46 | 47.32 |
| 同范围合成报告原值 | 82.00 | 82.00 |
| 重算减报告原值 | -0.54 | -34.68 |
| 正式等级 | 不提供 | 不提供 |

这里选择的是 `upper/main` 和 `upper/bear`。沿用原引擎这两个部位的权重0.70和0.12，并在选择范围内归一：

```text
第一次：(80×0.70 + 90×0.12) / (0.70+0.12) = 81.46（按展示精度）
第二次：(40×0.70 + 90×0.12) / (0.70+0.12) = 47.32（按展示精度）
```

未选择的一般构件、桥面系和下部结构不是被认定“不适用”或“完好”，只是**不在这个快照里**。因此不能用这个示例直接评桥。

## 输入不足时，宁可没有分数

新入口故意比历史函数严格：

- **空记录直接拒绝**。不会调用原 `evaluate_bridge([])`，也不会把“没有资料”写成“100分、I类”。原函数本身未改。
- **DP必须显式提供**，仅接受0至100范围内的有限普通实数。拒绝缺失、NaN、无穷大、负值、超范围值、布尔值和数值字符串。范围合法仅说明可参与本次数学演算，不证明DP符合具体规范。
- **构件类别必须明确已知**，实例必须是单个明确编号。未知类别、无编号、区间或合并实例不静默丢弃，避免越丢数据分越高。
- **数量必须覆盖**。选择部位的记录实例数须与对应结构数量一致，不替未记录实例补100。该检查只是声明范围的内部一致性，不认证现场数量。
- **适用性必须有明确布尔值和来源**。选择的部位却标不适用、适用性缺失或来源缺失，都进入复核，不出快照分。
- **已标待复核的输入不能直接算**。例如报告解析器输出 `engineering_verified=False`，不会被无缝包装成已核验DP。本例DP是独立提供的合成诊断输入，不能把解析器估计标度改名充当它。
- **原引擎若调整数量、发现未分类或暂定条件**，公开适配器停止交付数值并返回复核状态。

成功状态 `computed_snapshot` 仅表示受限范围内的计算完成。所有状态均保持 `formal_grade=None`、`publishable=False`。拒绝和待复核状态的 `calculated` 为 `None`。

## 报告原值与计算值各有来源

`reported` 轨保存调用方提供的原值、来源和声明范围，`calculated` 轨保存独立计算值、算法标识及输入哈希。每条DP还保留自己的输入来源。

只有两个声明范围完全一致时，适配器才显示数值差。如果报告原值是“全桥Dr”，当前演算却是“主梁+支座快照”，结果为 `not_comparable`，差值为空。即使范围一样，也仍需核对数据时点、输入口径和规范版本。

示例中即使差了34.68分，报告原值仍是82.00，重算值仍是47.32。**不以预设目标分数反向调整输入，不静默覆盖报告原值。** `automatic_overwrite_allowed=False`、`calibration_applied=False`。

输入哈希覆盖参与计算的记录字段和范围声明，不覆盖报告原值及每条记录的来源字符串；它用于复现实验的计算输入身份，不是签名或现场真实性证明。来源字符串是调用方的定位声明，仍需业务端验证对应资料是否真实存在。

## 适用范围与尚未实现的部分

公开适配器支持有明确数量契约的有限部位：主梁、支座、伸缩缝、铺装、护栏、排水、人行道、桥台、锥坡护坡。特殊桥墩柱/盖梁组合、一般构件混合、基础等需要专门的覆盖契约，本入口返回复核，不猜测。

本次没有重审原评分算法每一条规范依据，没有提供真实规范数据库，没有证明某一桥型符合某一评定方法，没有做强制等级规则的独立工程验收，也没有实现正式报告签发。因此不能以测试通过替代有资质人员的工程判断。

验证重点是：**DP进入了真实计算；缺数据不能被默认为满分；来源不会混合；差值不会被人为抹平。**
