# 反向 RAG：检索不是终点，输出仍要逐项核对

本例把原桥梁应用的检索、图遍历与输出验证实际接在一起。所有记录、分值与条款均为人工合成；`JTG 0000-2099` 是刻意使用的虚构编号，不是真实标准，不可用于工程评定。

## 原实现与新增适配

| 环节 | 代码来源 | 本例的行为 |
| --- | --- | --- |
| 双锚定检索 | 原 `RegulationRAGAgent.retrieve` | 先按构件和病害查询图谱，无结果再走原关键词排序。 |
| 图查询 | 原 `BridgeKnowledgeGraph.find_clauses` | 遍历显式关系，按给定权重排序，并保留 `graph` 来源。 |
| 引用与数值核验 | 原 `ClaimVerifier`、`claim_grounding` | 校验条款是否存在及相关性；数值绑定具体对象，而非只查全局数值集合。 |
| 报告出口合同 | 原 `verified_report_text` | 校验净化结果与问题计数是否有效；无正文时返回扣留说明，不回退到原答复。 |
| 内存构造与交付封装 | 新 `engineering_agent/evidence.py` | 调用者显式传索引和图；不读生产资料、不自动建私有图、不创建模型客户端。 |

`graph_from_relations` 只把调用者给出的关系变成原图对象，不从文本自动证明关系，也不把权重当成正确率。公开适配拒绝空条款索引，避免原验证器在缺少索引时降级成仅核对规范号，却被误称为完整条款验证。

## 一次合成运行

```text
显式内存条款 + 主梁/裂缝图关系
    → 原 RAG 检索
    → 候选答复
    → 原 ClaimVerifier 反向核对
        ├─ 错误数字 / 不存在条款：删除该句
        ├─ 已存在但不相关条款：保留警告，标待复核
        └─ 未发现已覆盖的冲突：保留正文
    → verified_report_text
        ├─ 验证异常 / 无有效正文：扣留
        └─ 仅交付净化后文本，不重新拼回原文
```

示例同时给出主梁风险评分 80、支座风险评分 30。候选句“主梁的风险评分为 30”不能因为 30 确实出现在另一条结果中就通过。核验按对象绑定发现冲突，删除该句；若整段只剩这句，报告出口扣留。

引用虚构索引中不存在的“第 9.9 条”会被硬删除。引用存在但只关联支座的“第 4.2 条”来解释主梁，会被软标记而非假装通过适用性认证。软标记文本允许展示供人复核，同时返回 `needs_review=true`；不能把它直接当作正式评定报告签发。

## 复现

在本仓库根目录运行：

```bash
python -m examples.reverse_verification
python -m unittest discover -s tests -p 'test_reverse_verification.py' -v
```

示例离线运行，无需密钥。测试对文件读取、私有图构建和网络连接设阻断，并检查：图遍历确实调用、错误对象数字被拦截、缺条款硬删除、无关条款软标记、仅返回净化文本、异常与损坏验证结果被扣留，以及空索引不能静默降级。

## 没有声称什么

1. **检索命中不是语义蕴涵证明。** 条款召回、存在性和构件/病害关联检查，并未证明候选答复的每个因果句都由原文推出。
2. **字段检查不是世界事实验证。** 本例假设传入结果供对账，未自动验证这些结果是否来自真实现场或正确规则计算。
3. **没有发现错误不是零幻觉。** 原检查器尚未覆盖任意自由文本推断；测试明确展示普通因果句可能留下，但输出始终标 `engineering_verified=false`。
4. **拒绝展示不是撤销外部动作。** 此处只控制文本交付，未发送工单、签发报告或改变真实资产状态。
5. **模型与 RAG 应区分。** 这份可复现示例用固定候选答复测试工程防线，没有调用模型，不能把输出称为本轮模型生成结果。

准确的描述是：**模型文本进入工程输出前，系统用当前证据对已覆盖的引用与数值主张做反向核验，核验决定会真实改变最终交付文本；仍未覆盖的推断交由专业复核。**
